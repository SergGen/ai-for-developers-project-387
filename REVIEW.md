# Ревью календаря звонков

Проверь изменения на указанном head SHA. Сопоставь их с исходным обращением, спецификацией, тикетами и комментарием согласования. Перечисли недоступные материалы и решения, выходящие за согласованный объём. Для инфраструктурного или релизного PR укажи его собственную цель.

## Поведение приложения

- Проследи путь от формы гостя через TypeSpec, сгенерированный контракт и Fastify до списка встреч владельца. Для каждой новой части данных проверь, к какой записи она относится, что видит гость после подтверждения и что происходит со старыми записями и клиентами.
- Для темы встречи проверь отсутствие значения, одни пробелы, границу 200 символов после удаления пробелов и превышение на один символ. Проверь, что ошибка понятна и запись не появилась. Учитывай действующий публичный доступ к предстоящим встречам.
- При изменениях бронирования проверь пересечение времени между типами встреч, соприкасающиеся интервалы и два одновременных запроса на один слот. У победителя сохраняются его данные, повторная запись отклоняется.
- Сопоставь основной, негативный и соседний сценарии с результатами тестов. Для браузерной проверки укажи, доступен ли артефакт для текущего head SHA. Если CI ещё выполняется, зафиксируй это.

## Риск, замечания и решение

Для изменений GitHub Actions проверь происхождение события, тип и права автора, область секретов и токенов, код, выполняемый с этими правами, учёт повторных попыток и остановку по бюджету. Для изменения данных проверь последствия отката и перезапуска процесса.

Для каждого подтверждённого дефекта назови файл и строку, условия воспроизведения и наблюдаемое последствие. Используй diff текущего коммита. При повторном ревью установи, какие предыдущие замечания исправлены или разобраны с объяснением. Если подтверждённых дефектов нет, сообщи об этом. Форматирование проверяет линтер.

Оставь текст ревью. Решение о слиянии принимает человек после проверки актуального SHA, CI и браузерного артефакта.
