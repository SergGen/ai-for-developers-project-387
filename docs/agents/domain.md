# Domain Docs

This repository has one domain context. Read `GLOSSARY.md` at the repository root and relevant decisions in `docs/adr/` before exploring the domain. If these files are absent, proceed. The `domain-modeling` skill creates them when the team settles a term or records a decision.

Use the glossary's terms consistently in code, tests, specs, and tickets. If a proposal conflicts with an existing ADR, point to that decision and explain what the proposal would change.
